# Will O'Wisp

Dungeon core **mentor companion**: tutorial delivery, contextual help, and upgrade notifications. See [Overall.md](./Overall.md) (guide companion pillar).

## Identity

- **Display name:** Will O'Wisp (codex title, first contact, occasional dry sign-off).
- **In dialogue:** “Will” or “the wisp”—not constant will-o'-the-wisp puns; tone matches **clean crystalline** pillar, not pun-heavy serial banter.

## Lore

- **Origin:** **Ley echo**—a pattern left in the capillary network when the core booted; not a living person, but behaves like a voice the core can hear.
- **Scout angle:** Can sense **one room ahead** of the powered influence radius (capillary “preview”), which justifies tutorial narration in places the core has not fully powered yet.
- **Late-game read (optional):** Ambiguity whether Will is only an echo or is accumulating personality as the core absorbs more patterns—light touch, no cutscene arc required.

## Role

| Responsibility | Notes |
| --- | --- |
| **Tutorial** | Onboarding for a newly awakened core; diegetic beats on real dig / power / breach actions. |
| **Help / Q&A** | Contextual codex: pre-authored answers keyed to game phase; deflect unknowns (“The grid doesn’t show that yet”). |
| **Upgrade alerts** | One message per unlock: **what**, **why it matters**, **where in UI**; duplicates stack into a single Will queue (no spam during essence bursts). |

## Voice and typography

- **Default voice:** Concise, slightly archaic, system-aware—short clauses, grid/essence vocabulary, rare warmth when the player does something clever.
- **Copy split** ([fonts.md](./fonts.md)):
  - **Telemetry-style** (Orbitron / Rajdhani): upgrade pings, objective nudges, system headers.
  - **Body / lore** (Goudy / Palatino): codex Q&A paragraphs and longer explanations.

## Delivery

- **Primary channel:** text (in-world voice to the core; HUD / dialogue panel).
- **Unprompted speech:** Upgrade unlocks + tutorial milestones; optional hints only when player invokes help or dismisses a beat—no repeating the same hint after dismiss.
- **Never:** block input, talk over core-defense panic, or use full-screen slides that break [Start Screen.md](./Start Screen.md) instant click / chain-reaction flow.

## Visual

- **Form:** Prism **wisp**—Shard Sentinel language ([General.md](./General.md)): small, faceless, refractive; motion = sharp darts and orbit, not soft fairy-tale flame.
- **Tutorial color:** **Pale violet (amethyst)** capillary/glow so players learn *violet = guidance* before ley-line zone states. Violet sits opposite the reserved teal/emerald and white-hot/red ranges, reads as non-threatening (unlike amber, which reads as caution), and matches the prism (violet is the last band refraction splits off).
- **Start screen tie-in:** The Continue / memory pulse on the start screen is **pale violet**, so the guidance color is taught before the first click (see [Start Screen.md](./Start Screen.md)).
- **Light spill:** Will casts soft, short-range violet light; spill on nearby surfaces (including the core) is fine and moves with him—never a fixed tint.
- **Colorblind backup:** Color never carries the meaning alone. Will's glow uses a **slow facet shimmer** (brightness cycling across facets, ~1–2s loop) that no powered, attack, or overload line uses. Powered lines stay steady or flow directionally; Will shimmers in place. Readable in grayscale.
- **Avoid:** body glow that reads as reserved system states in [General.md](./General.md) (teal/emerald/white-hot/red used for zone/power overload)—keep Will’s rim distinct from powered / attack / overload lines. Violet and the shimmer motion are reserved for Will; no zone state or core palette may use either.
